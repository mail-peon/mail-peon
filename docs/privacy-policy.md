# Mail Peon 隐私政策

> 适用版本：0.1.0 ｜ 生效日期：2026-01-01 ｜ 最后更新：2026-01-01
>
> 本政策描述 Mail Peon 浏览器扩展**当前实际的行为**，不是范本条文。
> 每条结论都在附录 A 里对应到源码位置，你可以自己核对。

## 摘要

- **我们没有服务器。** Mail Peon 没有后端，不接收、不存储、不查看你的任何数据。你的邮箱凭据、邮件与 AI Key 只存在于你自己的浏览器里。
- **对外请求只有三个去处**：① 你自己的邮箱（Gmail API，或你自己服务器上的 IMAP）；② 你自己配置的 AI 端点（只在你启用 AI 处理时）；③ 你自己运行的 IMAP 中继（默认就在本机 `127.0.0.1`）。
- **没有任何统计、遥测、崩溃上报、广告或远程配置**，也不存在「匿名上报使用情况」这类东西。
- **邮箱密码、OAuth token 与 AI Key 以明文存在本机**，浏览器扩展存储不做加密。
- **极简模式（默认）根本不保存邮件正文**，只留验证码与邮件头部。
- **你可以随时清空全部数据**，卸载扩展同样会删除。

## 1. 我们是谁

Mail Peon（下称"本扩展"）是一个开源的浏览器扩展，用于读取你授权的邮箱、挑出真正重要的邮件，并把其中的验证码自动复制到剪贴板。

**不适用范围**：

- 你自行修改、构建或第三方重新打包的版本 —— 其数据处理方式以该版本的代码为准。
- 你配置的 AI 平台、你的邮箱服务商（Google / 你的邮件服务器）、以及你自己运行的 IMAP 中继 —— 它们是彼此独立的服务或进程，适用各自的隐私实践。

## 2. 我们处理哪些数据

### 2.1 你主动提供的数据

| 数据 | 说明 | 是否必须 |
| --- | --- | --- |
| 邮箱连接配置 | IMAP 主机、端口、用户名、**密码**，或 Gmail 的 OAuth 授权结果 | 连接邮箱时必须 |
| AI 平台配置 | 平台、接口地址（BaseURL）、模型名、**API Key** | 使用任何 AI 功能时必须（含极简模式的验证码提取） |
| 提示词规则 | 按发件人 / 域名 / 正则匹配的自定义提示词 | 可选 |
| 排除名单 | 不处理的发件人或域名 | 可选 |
| 中继地址 | 你自己运行的 IMAP 中继地址（默认 `ws://127.0.0.1:8787/`），如需可带访问 token | 仅 IMAP 收信时需要 |

### 2.2 从邮箱读取的数据

**只读取你自己配置并启用的那些邮箱账号**，且只读取同步游标之后的增量邮件（每批最多 50 封）。读取内容：

- **邮件头部**：发件人、收件人、抄送、主题、收件时间、`Message-ID`、`List-Unsubscribe`。
- **邮件正文文本**：用于 AI 分类与验证码提取。**HTML 部分一律丢弃，不入库**；文本入库时截断在 5 万字符以内。
- **验证码本身**，以及邮件中写明的有效期。

**首次连接只记录同步位置，不拉取任何历史邮件。** 之后的每一轮同步也只取游标之后的新邮件。

### 2.3 本地生成的数据

- AI 输出：一句话摘要、要点摘要、是否为广告、验证码、紧急程度。
- 验证码的失效时刻与总有效期（用于页面上的倒计时进度条）。
- 处理状态：是否已复制验证码、是否已读、是否被你标记为「不再显示」。
- 回收站标记与删除时间（删除是可恢复的，见 3.3）。

### 2.4 我们不收集的数据

明确地、逐项地：

- **不收集任何账号体系信息**：没有注册、没有登录、没有用户 ID、没有设备指纹、没有安装 ID。
- **不读取你访问的其他网站**：内容脚本虽然注入所有页面，但它只在需要显示验证码提示条时才与你当前页面的 DOM 交互，**不读取、不上报页面内容**，不记录你访问了哪些网址（附录 A 第 10 项）。
- **不读取 Cookie**：代码中不存在任何读取 Cookie 的语句，也未申请 `cookies` / `webRequest` / `history` / `bookmarks` 权限。
- **不做统计与遥测**：全仓库检索 `analytics`、`telemetry`、`sentry`、`gtag`、`beacon` 等关键词均无匹配（附录 A 第 9 项）。
- **不含广告，不投放广告，不参与广告画像**（扩展自身会识别邮件里的广告，那是本地判断，不是广告投放）。
- **不向任何第三方出售、出租或交换你的数据。**
- **不加载任何远程代码**：发布版扩展页的 CSP 为 `script-src 'self'`，没有 CDN 脚本、远程字体或图标请求。

## 3. 数据存储在哪里、存多久

### 3.1 存储位置

全部数据存放在**扩展自己的 IndexedDB 数据库**（库名 `mail-peon`）里，分五个对象仓库：

| 仓库 | 内容 |
| --- | --- |
| `accounts` | 邮箱账号：地址、协议配置（含**明文密码**或 OAuth token）、同步游标、排除名单 |
| `rules` | 你的提示词规则 |
| `mails` | 邮件：头部、正文文本、AI 输出、验证码与失效时刻、回收站标记 |
| `settings` | 应用设置（`app`）与 AI 配置（`ai`，含 **API Key**） |
| `meta` | 一次性迁移标记（不含任何个人内容） |

除此之外**没有任何其他落盘位置**：不使用 `storage.sync`、不使用 `storage.session`，业务数据也不写 `chrome.storage`（该权限仅用于读取旧版本遗留数据完成迁移，见 5.1），不使用 Cookie，也不写文件系统。

**关键事实：**

- **明文存储。** 浏览器扩展存储不做加密，我们也没有额外加密。能读取本机浏览器配置目录的人（包括同一台电脑的其他使用者、能访问你磁盘的软件）就能读到其中的邮箱密码与 API Key。**建议使用设置了额度上限的 API Key，且不要用独立密码以外的复用密码。**
- **不随浏览器账号同步。** IndexedDB 不参与浏览器账号同步，不跨设备同步。
- **网站读不到。** 扩展存储与网页隔离，包括你收信的那些网站。
- **会请求浏览器持久化存储。** 首次初始化时会调用 `navigator.storage.persist()`，请浏览器不要把这份数据当作可回收的缓存清掉；这是尽力而为的请求（1 秒超时），失败也不影响使用。
- **导出文件里没有凭据。** 设置页的「导出」刻意不包含邮箱密码、OAuth token、AI Key，也不包含邮件正文 —— 导出的文件可以安全地自己留存。

### 3.2 保留期限与数量上限

- **完整模式**：邮件保留份数上限由你设置（默认 **100** 封，可选 200 / 500 / 1000 / 不限）。超出后每写入一封新邮件就自动丢弃最旧的一封；**回收站里的邮件不占这个名额**。
- **极简模式（默认）**：固定保留最近 **50** 条验证码，不暴露该设置。
- 无论哪种模式，启动时都会按当前设置清理一次，改设置后也会立刻清理一次。
- 数据本身**没有过期时间**，一直保留到你主动删除。

### 3.3 回收站与自动清理

- 删除是**可恢复**的：邮件被标记为「已进回收站」，不占保留名额，可在回收站页恢复。
- 只有「彻底删除」与「清空回收站」才会真正从数据库中移除记录（这两步都带二次确认）。
- **失效验证码默认自动进回收站**：AI 读出有效期后，扩展在失效时刻**再等 30 秒**（给推算误差留的宽限）把它移入回收站，而不是直接删除。该行为可以在设置中关闭。

### 3.4 如何删除

设置页 →「通用」→「清空所有数据」（含二次确认）。它会删除上述各仓库的全部内容：账号与凭据、提示词规则、邮件与 AI 结果、设置项。另有「清空邮件列表」只清邮件、保留账号与设置。

删除时的几个真实行为，提前说明：

- 删除后留在库里的是**默认空值**，因此"库还在"但内容已清空。
- **系统剪贴板里已复制的验证码不会被清掉**（扩展只写剪贴板，从不读取剪贴板）。
- 邮箱服务商自身的登录状态（Cookie）不受影响 —— 那本来就由你的浏览器管理，扩展碰不到。
- 卸载扩展，浏览器会一并删除这些数据。

**我们没有你的数据副本**，因此无法（也不需要）代你导出或删除。你自己就是数据控制者。

## 4. 数据什么时候离开你的设备

这是本政策最需要读清楚的一节。除下表所列情形外，**不发往任何地方**。

| 接收方 | 触发时机 | 实际发送的内容 |
| --- | --- | --- |
| **你配置的 AI 端点**（OpenAI / DeepSeek / Anthropic / 任意 OpenAI 兼容服务） | 收到新邮件、手动触发同步，或兜底定时任务发现新邮件时自动进行；也可由你在界面上主动测试连通性 | 邮件的**主题、发件人、时间、`List-Unsubscribe`**，以及**正文前约 6000 字符**（超出部分截断）。不含附件。极简模式只发同一封邮件的必要片段用于提取验证码。<br>连通性测试只发一句 `回复 ok`，**不发送任何邮件内容** |
| **Gmail API**（`gmail.googleapis.com`） | 启用 Gmail 账号并在同步或监听时 | 你的 OAuth 访问 token 与收信请求；返回的是你自己的邮件 |
| **Google OAuth**（`oauth2.googleapis.com`） | 你点击连接 Gmail、token 到期刷新、或你在设置中断开账号时 | 授权 / 刷新 / 撤销 token 所需的参数 |
| **你自己的邮件服务器**（IMAP 主机，经中继转发） | 同上 | 你的 IMAP 用户名与密码，以及 `LOGIN` / `SELECT` / `FETCH` 等 IMAP 命令 |
| **你自己运行的 IMAP 中继**（默认 `ws://127.0.0.1:8787/`） | 你配置了 IMAP 账号并启用时，插件会主动连上去 | IMAP 通信字节流，用于把 WebSocket 转成 TCP。**推送消息里只有「有几封邮件」这个事实，不含主题与正文** |

补充说明：

- **请求中不含任何身份标识。** 发往 AI 端点的请求体里只有提示词与邮件内容，没有用户 ID、安装 ID、设备指纹、邮箱地址或扩展版本号；唯一"标识"是你自己的 API Key（放在请求头里，不放在 URL 里）。由于是普通跨域请求，请求会带上扩展自身的 `Origin` 头。
- **超时与重试。** AI 请求 90 秒超时（连通性测试 20 秒），**没有自动重试**，失败即失败（完整模式下会降级显示邮件的基础信息，极简模式下会丢弃该封邮件）。
- **本地模型完全不出本机。** 在「自定义」平台里填 `http://localhost:11434/v1`（Ollama）或 LM Studio 等本地地址时，邮件内容不会离开你的电脑 —— 这是唯一一种内容全程不由第三方经手的配置。
- **IMAP 收信需要中继，这是浏览器能力限制**，不是可选设计：扩展没有裸 TCP 能力，必须由中继把字节搬进 TCP。详见第 7 节。

### 4.1 各 AI 平台的默认地址

扩展内置以下预设，接口地址与模型都可以自己改：

| 平台 | 默认接口地址 | 默认模型 |
| --- | --- | --- |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-flash` |
| Anthropic | `https://api.anthropic.com` | `claude-3-5-haiku` |
| 自定义端点 | 需自行填写（可填本地模型地址） | 需自行填写 |

## 5. 权限与页面访问

### 5.1 申请的权限，以及各自的用途

| 权限 | 用途 | 说明 |
| --- | --- | --- |
| `tabs` | 定位当前窗口的活动标签页，把「验证码已复制」的提示条投递到该页面的内容脚本 | 该权限在技术上允许读取所有标签页的 URL/标题；代码中只查询"当前窗口的活动标签页"并取它的 id，**不遍历、不记录、不上传**其他标签页地址（附录 A 第 11 项） |
| `activeTab` | 当前版本代码中没有任何一处依赖它 —— 定位标签页完全由 `tabs` 完成 | 如实说明：这属于一份可以收窄的多余权限面，我们计划在下个版本评估移除 |
| `alarms` | 注册一个低频（**10 分钟**）兜底任务：推送链路断掉时仍能发现新邮件，并清理过期的验证码 | 不在后台采集任何数据；正常收信靠中继推送，不靠它 |
| `sidePanel` | 用浏览器原生侧边栏承载完整界面（全部 / 重要 / 验证码 / 营销） | 界面不注入页面，不遮挡、不打扰 |
| `identity` | **仅用于 Gmail 的 OAuth 授权**（`launchWebAuthFlow`） | 不使用 Gmail 的用户此项不会被使用；扩展不接触你的 Google 账号密码 |
| `storage` | **仅用于读取旧版本遗留的 `chrome.storage.local` 数据以完成一次性迁移** | 迁移校验无损后才删旧键；日常读写走扩展自己的 IndexedDB，不需要任何权限，也不上传 |
| 主机权限 `https://gmail.googleapis.com/*`、`https://oauth2.googleapis.com/*` | 读取你授权的 Gmail 邮件、刷新 / 撤销 OAuth token | 与你在设置里连接的账号一一对应 |
| 主机权限 `*://*/*` | **仅为了让常驻内容脚本能在任意页面上显示验证码提示条** | 这是本扩展最大的一处权限面，如实说明：它使内容脚本可以运行在所有页面，但脚本不读取页面内容、不修改页面外观、不拦截网络请求；空闲时不挂载任何 DOM |

### 5.2 页面里的脚本做了什么

只有一件事：在需要提示时，用 **closed shadow DOM** 创建一条页面顶部的提示条（"验证码已复制 / 点击复制"），并在你点击或页面有焦点时调用 `navigator.clipboard.writeText` 把验证码写进剪贴板。

- 提示条自带内联样式，不加载任何外部资源，也不声明 `web_accessible_resources` —— 页面脚本无法通过已知资源路径探测到扩展。
- 脚本**不读取**页面的 DOM 内容、表单、输入框或 localStorage / sessionStorage，不向你访问的网站发起任何请求。

### 5.3 明确不做的事

- 不读取 Cookie（未申请 `cookies` / `webRequest` / `history` / `bookmarks` 权限）。
- 不读取你访问的其他任何网站的内容或浏览记录。
- 不向页面注入任何表单或按钮，不代填、不点击页面元素。
- 不批量采集：没有爬虫、没有队列，只读取你自己账号里游标之后的增量邮件。
- 不加载任何远程代码（见 2.4）。

## 6. 第三方如何处理你的数据

我们把数据交给你选择的服务提供者之后，**其后续处理由它们各自的政策决定，我们无法控制也无法撤销**：

- **AI 平台**接收邮件的主题、发件人与正文片段，可能按其条款保留日志、用于模型改进或人工审阅。请自行阅读其隐私政策与服务条款，优先选择明确承诺"不用于训练"的 API 条款，或直接使用本地模型端点。
- **Google**：使用 Gmail 账号时，邮件数据由 Google 提供，OAuth 授权关系由 Google 管理，可随时在 <https://myaccount.google.com/permissions> 撤销。
- **你的邮箱服务商**：你与它之间本来就有既存的服务关系与隐私政策。
- **你自己运行的 IMAP 中继**：它不是我们运营的服务，是你自己机器上的一个进程，其行为由你自己（以及你选择部署它的方式）决定。

关于 Google API 数据的额外声明：本扩展对 Gmail 数据的访问与使用遵循
[Google API 服务用户数据政策](https://developers.google.com/terms/api-services-user-data-policy)（含 Limited Use 要求），
**仅用于实现本扩展唯一且明确的功能**（挑出需要你看的邮件并提取验证码），
不会转售、不会用于广告或广告画像、不会用于信用评估或借贷，也不允许人工读取你的邮件内容。

## 7. 关于本机 IMAP 中继

浏览器扩展无法直接建立 IMAP 所需的 TCP 连接，因此 IMAP 收信需要一个中继。中继的源码随仓库一同提供（`scripts/imap-relay.ts`），由**你自己运行**：

- **默认只监听 `127.0.0.1`**，即只有本机能连上；绑定到非本机地址时会明确警告，并建议设置 `RELAY_TOKEN`。
- **不落盘、不解析邮件内容**：它只解析 `LOGIN` / `SELECT` / `IDLE` 的响应行，用来知道"有没有新邮件"。
- **但它能看到明文。** 常驻监听模式下中继需要自己终结与邮件服务器之间的 TLS（否则读不到 `EXISTS` 响应），因此它在运行期间握有解密后的字节流，**包括你的邮箱密码**。这不是缺陷，而是 TLS 语义决定的必然结果。

**结论：请不要把中继暴露到公网，也不要在不受信任的机器上运行它。** 详见
[`ai-docs/decisions/adr-0005-imap-needs-relay.md`](../ai-docs/decisions/adr-0005-imap-needs-relay.md)。

## 8. 安全

- **传输**：对 Gmail API、Google OAuth 与你选的云端 AI 平台的请求全部走 HTTPS；IMAP 经中继走 TLS（993）。唯一例外是你自己填的本地或自建端点（如 `http://localhost:11434`），那是你与你自己端点之间的通信。
- **存储**：依赖浏览器提供的扩展存储隔离 —— 网页与扩展之间、扩展与扩展之间互相隔离；但**本地存储本身不加密**。
- **风险面**：由于我们没有服务器，不存在"服务端数据泄露"这一类风险；实际风险只有三处 —— ① 你本机的浏览器配置目录被他人读取；② 你选择的 AI 平台如何处理你发过去的内容；③ 你把中继暴露到公网。
- **降低风险的建议**：
  1. 用设置了额度上限的 AI Key，并定期轮换。
  2. 不要在公共或共用电脑的浏览器里保存长期有效的邮箱密码与 Key（设置页也有同样的提示）。
  3. 敏感邮件改用本地模型端点（如 Ollama），让正文不出本机。
  4. 如果只是想要验证码，保持**极简模式**：正文根本不入库，能显著缩小本机数据的暴露面。
