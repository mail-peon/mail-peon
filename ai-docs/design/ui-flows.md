## 1. Popup（点工具栏图标）

> 渲染 `popup/Popup.vue`，根据 `AppSettings.minimalMode` 切两套。

### 1.1 自定义模式（默认）

固定 360 × 480 窗口。筛选标签由「状态标签 + 适配器标签」动态生成（Feature 08）：

```
┌─ mail-peon ───────────────────────┐
│ [重要 5] [全部 12] [验证码 1] [确认 2] [营销 3]  ← 动态 tabs
├────────────────────────────────────┤
│ ┌──────────────────────────────┐  │
│ │ GitHub · noreply@github.com │  │
│ │ 你订阅的 repo 有了新 PR       │  │
│ │ [high] 5 分钟前               │  │
│ │ 点击展开 → summary            │  │
│ └──────────────────────────────┘  │
│ ┌──────────────────────────────┐  │
│ │ 阿里云 · alert@aliyun.com    │  │
│ │ 服务器 CPU 异常              │  │
│ │ [high] 12 分钟前              │  │
│ └──────────────────────────────┘  │
│                                    │
│              [打开 Options 完整面板] │
└────────────────────────────────────┘
```

> 标签的来源：
> - **状态**：`重要`（!Ad && (!Low || 验证码/确认)）、`营销`（Ad 位）
> - **内置适配器**：`验证码`、`确认邮件`
> - **自定义适配器**：用户自己的类型名
>
> `全部` 永远在；`总结` 不作为筛选标签。极简模式不显示筛选 tab（平铺列表）。

## 2. Sidepanel（从浏览器侧边栏菜单打开）

比 Popup 宽（≥ 400px），可以常驻。所有 popup tab 在这里都展开成"完整列表"。

> ⚠️ **不是「点击工具栏图标 = 打开侧边栏」**。代码**刻意没有**调
> `sidePanel.setPanelBehavior({ openPanelOnActionClick: true })` ——
> 它与「点图标打开 Popup」互斥，而产品要求的是后者
> （见 `background/main.ts` 的说明）。侧边栏从浏览器自带的侧边栏菜单进。

```
┌─ mail-peon ───────────┐  ┌─ 主区 ──────────────────┐
│ [重要] [全部] [验证码]   │  │ 邮件标题 1               │
│ [营销]                   │  │ from / 时间             │
│                          │  │ summary                │
│ ┌── 邮件 1 ─────────┐   │  │ ...                    │
│ │ 标题                │   │  └────────────────────┘
│ │ from / minimal     │   │  ┌────────────────────┐
│ └────────────────────┘   │  │ 邮件标题 2            │
│ ┌── 邮件 2 ─────────┐   │  │ ...                  │
│ │ ...                │   │  └────────────────────┘
│ └────────────────────┘   │
└──────────────────────────┘
```

> 左侧栏 = 邮件列表；右侧 = 选中邮件详情（点开才有）。MVP 阶段可以先做单栏。

## 3. 通知反馈（Badge + 页面 Toast）

> **不使用 `chrome.notifications`**。改用：
> 1. **Badge**：icon 右上角数字提示"有新邮件未看"——用户点 icon = 看 Popup
> 2. **页面顶部 Toast**：验证码自动复制等"刚做完一件事"的反馈——不抢焦点、不打扰

详细 toast 设计见 [`./page-toast.md`](./page-toast.md)。

### 3.1 Badge（icon 上）

```
   ┌──┐
   │🔔│  ← mail-peon 图标
   └──┘
   3   ← badge 数字 = 未读且非广告且非已复制验证码 的邮件数
```

- 用户**点击 icon = 打开 Popup**（Chrome 默认行为；不需要 `chrome.action.onClicked`）
- 打开 Popup → 当前 tab 的 badge 归零；用户"标记已读"也算清零；同时立即检查一次新邮件

### 3.2 页面顶部 Toast（content script 渲染）

> 在当前激活页面**顶部居中**，堆叠显示。详细规范见 [`./page-toast.md`](./page-toast.md)。

**自动复制成功：**

```
┌────────────────────────────────────────────────┐
│ GitHub · noreply@github.com                  × │
│ 验证码  123456                                 │
│ √ 已复制                                       │
└────────────────────────────────────────────────┘
```

**自动复制失败：**

```
┌────────────────────────────────────────────────┐
│ GitHub · noreply@github.com                  × │
│ 验证码  123456                                 │
│ 自动复制失败  复制                             │
└────────────────────────────────────────────────┘
```

**未开自动复制：**

```
┌────────────────────────────────────────────────┐
│ GitHub · noreply@github.com                  × │
│ 验证码  123456  复制                           │
└────────────────────────────────────────────────┘
```

- 第一行 = 发件人 · 发件邮箱，右端 `×` 关闭；第二行 = 验证码（22px 主体字号），
  **永远只有验证码**
- 成功态第三行是**灰色**的 `√ 已复制`（不强调）；失败说明进第三行；
  复制按钮是**文字按钮**（与 Popup 列表项里那个同款），
  未开自动复制时**不写状态词**、按钮直接跟在验证码后面
- 成功态没有 emoji，状态由左侧 4px 色条表达
- 整条点击 → 打开 Popup 并定位该邮件
- "复制"按钮 → 在当前页面调用 `clipboard.writeText` → 就地换成 `√ 复制成功`
- 5 秒自动消失（hover 暂停）

## 5. 通知场景矩阵（汇总）

> Badge = `chrome.action.setBadgeText`；Toast = 页面顶部弹窗（详见 [`./page-toast.md`](./page-toast.md)）。

| 场景 | Badge | Toast | 验证码分区 |
| --- | --- | --- | --- |
| 普通邮件 | +1 | ❌ | — |
| AI 判定广告 + 排除 ON | ❌ | ❌ | — |
| AI 判定广告 + 排除 OFF | +1 | ❌ | — |
| 含验证码 + 自动复制成功 | ❌ | ✅ "验证码 123456" + 灰色 "√ 已复制" | ✅ |
| 含验证码 + 自动复制失败 | +1 | ✅ 第三行"自动复制失败 复制" | ✅ |
| 含验证码 + 自动复制 OFF | +1 | ✅ "验证码 123456 复制"（无状态词） | ✅ |
| 在排除邮箱 | ❌ | ❌ | — |
