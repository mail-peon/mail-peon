# ADR-0006 · 邮件类型适配器与 `mailTypes` 仓库

- 状态：已接受
- 日期：2026-10-22
- 相关：[`../features/08-mail-types.md`](../features/08-mail-types.md)

## 背景

MVP 的「类型」是写死的：

- `AiOutput` 只有 `code` 一个结构化类型；
- `isAd` / `urgency` 是 AI 输出里的两个字段，和「类型」混在一起；
- 提示词只有一份「总结 + 验证码」大 schema；
- UI 只有验证码面板；列表是硬编码的四个 tab。

产品要加「确认邮件」类型，并且允许用户自定义类型、允许一封邮件同时命中多个类型。
继续在 `AiOutput` 上叠字段会让类型系统越来越像一堆 `if`。

## 决策

### 1. 引入 `MailTypeAdapter` / `MailTypeMatch`

- **适配器** = 类型 + 提示词 + 开关 + 优先级 + 是否兜底。
- AI 一次调用返回 `types: MailTypeMatch[]`，每个 match 带自己的结构化数据。
- 「总结」也是一个适配器，且是兜底（没有其它类型命中时才生成）。

### 2. 邮件状态用位掩码

- `Mail.stateFlags: number`，`Ad = 1 << 0`、`Urgent = 1 << 1`、`LowPriority = 1 << 2`。
- AI 输出字符串数组 `states`，JS 转位掩码；不让模型做位运算。
- `AiOutput` 不再写 `isAd` / `urgency`；老数据在归一化时迁移。

### 3. 新增 IndexedDB 仓库 `mailTypes`

- `DB_VERSION` 2 → 3。
- 外部键（`id`），无索引。
- **内置适配器不落库**：代码里的 catalog + 用户的 override 记录。
- 自定义适配器整条记录存这里。
- 理由：
  - 新增内置类型不需要写「播种 / 迁移」；
  - 清空数据后内置仍在；
  - 删除 override 即恢复默认；
  - 与「内置默认规则不落库」保持同一套心智。

### 4. 模式 = 生效层 overlay

- 极简模式强制只生效 `builtin:code` + `builtin:confirm`，其余关闭；
- 自定义模式按保存的开关生效；
- 切换模式**不修改**保存的适配器状态，避免临时切模式把用户配置清掉。

### 5. 列表筛选改为动态标签

- 状态标签（重要 / 营销）+ 内置适配器标签 + 自定义适配器标签；
- 不再硬编码 `PopupTab` 四个值；
- `popupDefaultTab` 变成字符串筛选 id，旧值做映射。

## 后果

### 正面

- 加新类型 = 加一个 catalog 条目 + 一段提示词，不动流水线。
- 多类型共存是数据模型的一等公民，不是特判。
- 状态标签可扩展：以后加 `NeedsReply` 只是一个新 bit。
- 历史数据可读：`ai.code` / `ai.summary` 归一化时合成 match。

### 代价

- `AiOutput` 的消费方（列表、badge、筛选、卡片）要改一轮。
- 每封邮件的 prompt 变大（所有启用适配器都要带上）；用配置页预算提示与正文压缩兜底。
- 内置适配器需要维护中英两套提示词。
- 列表筛选从固定四 tab 变成动态，`popupDefaultTab` 需要处理「指向已删除适配器」。

### 被否决的方案

| 方案 | 否决原因 |
| --- | --- |
| 每个适配器调一次 AI | 成本 × N、延迟叠加、多类型结果可能互相矛盾 |
| 两段式「先分类再抽取」 | v1 过度设计；一次调用已足够 |
| 内置适配器也落库 + 首次播种 | 新版本加内置类型要写迁移；清空数据后要记得重播 |
| 状态标签继续放 `AiOutput` | 与「类型」耦合，关掉总结会连带广告 / 紧急失效 |
| 模式切换直接改写适配器开关 | 临时切到极简会清掉用户的自定义配置 |
